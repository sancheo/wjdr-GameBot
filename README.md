# 无尽冬日GameBot

目前实现《无尽冬日》安卓模拟器上的**联盟互助、探险经验领取、士兵训练、联盟科技捐献、免费英雄招募、宠物寻宝、仓库补给、生命之树、晨曦回礼、宠物技能、灯塔情报、自动打怪和资源采集**，并支持**强制下线后重连**。

以下说明适用于 **Windows 10/11 64 位便携版**，通过 GUI（图形界面）配置、运行和排查问题。程序通过 ADB 截图、识别画面并向本机 Android 模拟器发送点击操作。

## 安装与使用

压缩包已包含 **Python、程序依赖、OCR 模型、ADB、Visual C++ 运行库和 WebView2 运行环境**，无需另行安装 Python、pip 或这些组件。电脑仍需安装 Android Studio，准备安卓模拟器、系统镜像和游戏。

### 第 1 步：安装 Android Studio 和模拟器组件

1. 从 [Android Studio 官网](https://developer.android.com/studio) 下载并安装 Android Studio。
2. 第一次启动时选择 **Standard（标准）**设置，完成安装向导。
3. 在欢迎页打开 **More Actions → SDK Manager**；如果已经打开项目，则选择 **Tools → SDK Manager**。
4. 打开 **SDK Tools** 标签页，勾选 **Android SDK Platform-Tools** 和 **Android Emulator**。
5. 点击 **Apply**，等待下载和安装完成。

如果提示需要开启硬件虚拟化或安装模拟器加速组件，请按 Android Studio 的提示完成配置并重启电脑。

### 第 2 步：创建 Pixel 5 模拟器

1. 在 Android Studio 欢迎页打开 **More Actions → Virtual Device Manager**；如果已经打开项目，则选择 **Tools → Device Manager**。
2. 点击 **Create Device**，在 **Phone** 分类中选择 **Pixel 5**，然后点击 **Next**。
3. 下载并选择 **API 34** 的 Android 系统镜像。
4. 保持默认竖屏 **1080×2340** 分辨率，点击 **Finish**。
5. 点击设备右侧的启动按钮，等待安卓桌面完全出现。

请使用 Android 模拟器，实体手机不在支持范围内。Android Studio 创建的模拟器无需另外开启 USB 调试。

### 第 3 步：在模拟器中准备游戏

1. 在模拟器中点击浏览器输入taptap.cn下载并安装 TapTap，再通过 TapTap 安装《无尽冬日》国服。
2. 打开游戏，登录账号，进入主城。
3. 让游戏保持在模拟器前台。
4. 关闭电脑和模拟器的自动休眠，运行期间保持电脑、模拟器和游戏开启。

GameBot 不会自动安装模拟器、安装游戏或登录游戏账号。

### 第 4 步：解压并打开 GameBot

1. 将整个便携版压缩包解压到当前用户可写的本地目录，例如 `D:\GameBot`。不要在压缩包预览窗口中直接运行，也不要使用网络共享目录。
2. 完整保留解压后的文件和文件夹，尤其是 `runtime/`、`.tools/` 和 `assets/`，不要只复制 `GameBot.exe`。
3. 双击解压目录中的 **GameBot.exe**，等待 GUI 打开。
4. 点击“刷新”，在模拟器列表中选择已准备好的 Pixel 5。未启动的模拟器可通过列表中的“启动”按钮开启，等待状态变为“已启动”后再继续。

程序默认从 `%LOCALAPPDATA%\Android\Sdk` 查找模拟器组件。如果 Android Studio 使用其他 SDK 目录，请按下方常见问题配置。

### 第 5 步：通过 GUI 验证并运行任务

1. 首次使用时，在 GUI 中仅开启“联盟互助”，点击“启动”。
2. 查看模拟器中的实际操作，以及 GUI 的“任务执行状态”和“运行日志”，确认主城识别、点击位置和任务执行正常。
3. 点击“停止”，等待任务停止后，再逐项开启需要的功能并重新启动，确认各项任务正常。
4. 出现问题时，查看 GUI 的“异常信息”或异常退出提示，按其中显示的路径打开异常截图，结合当时的游戏画面排查。

同时启动多台模拟器时，请在 GUI 中选择本次要运行的设备。修改任务配置前先停止任务。

## 常见问题

### 还需要安装 Python 吗？

使用便携版压缩包不需要。GUI 会直接使用 `runtime/` 中的 Python 和依赖，无需配置 Python 环境或安装项目依赖。如果提示 Python 或依赖缺失，请重新完整解压便携包，并确认 `runtime/` 未被删除或隔离。

### 程序异常时如何排查？

1. 查看 GUI 的“任务执行状态”，确认出问题的任务及停用原因；再查看“运行日志”中的红色“异常信息”或异常退出提示。
2. 根据异常信息显示的完整路径，在文件资源管理器中打开异常截图，检查是否停留在弹窗、登录页面、错误页面或其他非预期界面。
3. 手动处理异常界面并返回主城。程序仍在运行且任务已停用时，可在“任务执行状态”中点击该任务的“单项重试”；任务运行已停止时，处理问题后重新点击“启动”。
4. 如需反馈问题，请提供任务名称、发生时间、GUI 异常信息和对应异常截图。

任务首次异常后，程序每隔 10 秒尝试恢复主城并重试，最多连续重试 3 次。第 3 次重试仍失败时，会在恢复界面前保存当前模拟器的彩色截图，并在 GUI 中报告原因和截图路径，随后停用该任务。前面的失败会记录日志，但不一定生成截图。已停用的任务在强制下线重连后仍保持停用，可通过“单项重试”重新验证；重新启动任务运行也会恢复执行。

异常截图保存在解压目录的 `artifacts/exception_screenshots/<模拟器>/<YYYY-MM-DD>/` 下，按模拟器和日期分类，保留 7 天并自动清理。请及时保存需要反馈的截图。若模拟器断开、ADB 不可用或截图保存失败，GUI 会显示相应原因；此时请提供异常信息。

### GUI 中没有模拟器或模拟器未就绪

先在 Android Studio 的 **Device Manager** 中确认已经创建 Pixel 5，并启动模拟器，等待安卓桌面完全出现。回到 GameBot 点击“刷新”，选择状态为“已启动”的设备。

仍无法识别时，先停止任务，再通过模拟器列表中的“重启”按钮重启设备，或从 Device Manager 关闭后重新启动，然后回到 GUI 刷新。若提示未发现模拟器，请确认 Android SDK 和虚拟设备已完成配置。

GameBot 不显示通过 USB 连接的实体手机。

### Android SDK 安装在其他位置

在 Android Studio 的 **SDK Manager** 中查看 **Android SDK Location**。通过 Windows“编辑账户的环境变量”添加或修改用户变量 `ANDROID_HOME`，将其值设置为该 SDK 目录，然后关闭并重新打开 GameBot，在 GUI 中点击“刷新”。

### 找不到 ADB 或提示无法启动 ADB

便携包已带有 ADB。先确认完整解压了压缩包，且 `.tools/platform-tools/` 中的文件没有被删除或隔离；文件缺失时重新解压。

同时在 Android Studio 的 **SDK Manager → SDK Tools** 中确认 **Android SDK Platform-Tools** 和 **Android Emulator** 已安装。安装或修复后，重新打开模拟器与 GameBot，在 GUI 中刷新并验证连接。

### 提示屏幕尺寸不正确

程序收到的游戏截图必须是 **1080×2340**，缩放模拟器在电脑上的窗口不会改变截图分辨率。请在 Device Manager 中重新创建默认分辨率的 **Pixel 5**，按第 2 步完成配置，再回到 GUI 选择新设备并验证。

### 提示游戏不在前台或无法确认主城

进入模拟器，确认显示的是《无尽冬日》国服中文界面的主城，关闭活动弹窗，退出登录页或其他应用。处理后回到 GUI 重新启动任务，或对已停用的任务点击“单项重试”。若仍失败，请结合 GUI 异常信息和异常截图排查。

非国服、非中文界面或游戏界面大幅改版时，现有识别素材可能不适用。

### OCR 加载失败或 GUI 无法打开

确认使用的是 **Windows 10/11 64 位**，并已完整解压便携包。不要单独移动 `GameBot.exe` 或删除 `runtime/`、`assets/` 中的文件。

关闭程序后，将便携包重新解压到当前用户可写的本地目录，再双击 `GameBot.exe` 验证。若仍失败，请提供启动提示；能进入 GUI 时，同时提供其中的异常信息和异常截图（如已保存）。

### 如何更新或保留配置？

程序启动后会在后台检查 [GitHub Releases](https://github.com/sancheo/wjdr-GameBot/releases) 的最新正式版本，也可以点击 GUI 右上角的“检查更新”。检查失败不会影响自动任务，可在网络恢复后重试。此功能无需安装 Git 或其他软件，只需要能访问 GitHub。

发现新版本后，可展开“更新说明”，点击“下载”查看下载进度。下载期间现有任务继续运行；程序会校验压缩包的大小、SHA-256、版本和目录结构。

下载并校验完成后，点击“安装并重启”。程序会停止当前自动任务并退出，由包内的 `GameBot.Updater.exe` 替换程序和运行环境，完成启动检查后重新打开 GUI。`configs/` 配置、`logs/` 日志和 `artifacts/` 截图会保留。更新后任务保持停止，请检查配置后手动启动。安装或新版启动检查失败时，会尝试恢复旧版，并显示错误；若恢复失败，提示会给出备份目录。

安装更新前，请关闭同一解压目录中其他 GameBot 窗口，等待模拟器启动或重启完成，并留出至少压缩包大小四倍加 512 MiB 的磁盘空间。不要删除 `GameBot.Updater.exe`。自动更新面向公开仓库的完整 Windows 便携发行包，草稿、预发布版本和源码 ZIP 不用于自动安装。

旧包没有更新功能或网络无法下载时，可停止任务并关闭旧程序，将新版便携包完整解压到新目录，再复制旧目录的 `configs/`。需要保留旧日志、异常截图时，同时复制 `logs/` 和 `artifacts/`，随后打开新版 GUI 检查设置。

## 发布新版本（维护者）

在 Windows 开发环境中使用项目 `.venv` 运行打包脚本。版本号使用 `1.0.1` 这样的三段数字，每次正式发布递增；`--webview-runtime` 指向官方 x64 WebView2 Fixed Version 的解压目录：

```powershell
.venv\Scripts\python.exe -X utf8 scripts\build_portable.py --version 1.0.1 --webview-runtime "官方 WebView2 运行环境目录"
```

如果开发环境使用 `opencv-python`，还需传入 `--opencv-headless-wheel "匹配当前 OpenCV 版本的官方 win_amd64 wheel 路径"`。打包会生成独立运行环境、版本元数据和更新器，执行便携环境及 GUI 自检，并在 `dist/` 输出 `GameBot-Windows-x64-v1.0.1.zip` 和 `GameBot-Windows-x64-v1.0.1.zip.sha256`。

在上述仓库创建 GitHub Release，标签填写 **v1.0.1**，填写更新说明，同时上传这两个文件，然后发布为正式版本。标签、包内版本及附件文件名必须一致，不要勾选预发布。后续用户就能在 GUI 检测、下载并安装该版本。GitHub 自动生成的 Source code 附件不包含运行环境，不能代替便携包。

本次首个带更新功能的便携版为 **v1.0.0**。此前的旧版需要手动解压更换一次，后续即可使用 GUI 更新。若迁移 GitHub 仓库，需同步修改 `app_version.py` 和 `desktop/Updater.cs` 中的仓库标识后重新打包。
